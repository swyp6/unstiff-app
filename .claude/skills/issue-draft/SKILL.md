# Issue Draft

이 저장소(`swyp6/unstiff-app`)의 `.github/ISSUE_TEMPLATE/*.md` 양식 그대로 이슈 초안을 만든다. 항상 초안을 먼저 보여주고, 사용자가 명시적으로 확인한 뒤에만 실제로 생성한다.

## 규칙

1. **초안 우선, 생성은 확인 후에만.** `gh issue create`는 사용자가 초안을 보고 "만들어줘", "등록해줘" 등으로 확인하기 전에는 절대 실행하지 않는다.
2. **모르는 내용은 지어내지 않는다.** 재현 방법, 실행 환경, 완료 조건처럼 대화나 코드에서 확인 안 된 항목은 템플릿의 안내 주석을 그대로 남기거나 사용자에게 물어본다.
3. **템플릿 구조를 임의로 바꾸지 않는다.** 섹션 제목, 순서, 체크리스트 형식은 원본 템플릿 그대로 유지한다.
4. assignees는 사용자가 지정하지 않으면 비워둔다.

## 흐름

1. **이슈 종류 판별** — 대화 맥락(버그 리포트 vs 새 기능 vs 잡무 vs 리팩터 vs 문서)으로 종류를 정한다. 애매하면 사용자에게 묻는다.

   | 종류      | 템플릿                               | 라벨       |
   | --------- | ------------------------------------ | ---------- |
   | 버그      | `.github/ISSUE_TEMPLATE/bug.md`      | `bug`      |
   | 기능      | `.github/ISSUE_TEMPLATE/feature.md`  | `feature`  |
   | 일반 작업 | `.github/ISSUE_TEMPLATE/task.md`     | `task`     |
   | 리팩터    | `.github/ISSUE_TEMPLATE/refactor.md` | `refactor` |
   | 문서      | `.github/ISSUE_TEMPLATE/document.md` | `document` |

2. **해당 템플릿 파일을 읽어** 섹션 구조를 그대로 가져온다.
3. **내용 채우기** — 지금까지의 대화, 관련 코드/커밋을 근거로 각 섹션을 채운다. 근거가 없는 섹션은 원본의 안내 주석(`<!-- ... -->`)을 남겨두거나, 필요하면 사용자에게 되묻는다.
4. **초안을 마크다운 코드블록으로 채팅에 보여준다.** title은 템플릿의 `title:` 접두사(`[Bug] `, `[Feature] ` 등)를 유지한다.
5. **사용자 확인 대기.** 수정 요청이 있으면 반영 후 다시 보여준다.
6. **확인되면 생성:**
   ```bash
   gh issue create --title "<확정된 제목>" --label "<위 표의 라벨>" --body "$(cat <<'EOF'
   <확정된 본문>
   EOF
   )"
   ```
7. 생성된 이슈 URL을 사용자에게 전달한다.
